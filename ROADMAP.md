# CloudNode roadmap

**Stage: pre-alpha** · next: M1 (the vault)

> **Last updated:** 2026-10-23 · **Change:** app icon renders (M6) and draft-release builds on `main` (M7)

Each milestone ends with `cargo xtask ci` green and the change described here. Tick a box in the
same change that lands the work.

## M0: Workspace skeleton (done)

- [x] Cargo workspace (`crates/*`, `apps/*`, `xtask`), edition 2024, shared lints
- [x] Crates by layer: `core`, `vault`, `ssh`, `term`, `ui-slint`, `ui-tui`; layering checked by `cargo xtask layers`
- [x] Two binaries: `cloudnode` (Slint window) and `cloudnode-tui` (Ratatui console), both showing empty lists
- [x] Colour tokens in `cloudnode-core` shared by both interfaces; Slint metrics in `ui/theme.slint`
- [x] MIT OR Apache-2.0, `NOTICE`, `ATTRIBUTION.md`, the TradeCloud brand license
- [x] `AGENTS.md`, `CLAUDE.md`, `README.md`, `SECURITY.md`

## M1: The vault

- [ ] File format: header (magic, format version, Argon2id salt and costs), XChaCha20-Poly1305 payload, header as associated data
- [ ] Create, unlock, change master password, lock on idle
- [ ] Hosts, groups and keys stored and validated on load (`Host::validate`)
- [ ] Secrets zeroized, redacted in `Debug`; wrong password and damaged file give clear errors
- [ ] Data folder per platform (`~/Library/Application Support/CloudNode`, `%APPDATA%\CloudNode`, `~/.local/share/cloudnode`)

## M2: SSH sessions

- [ ] Connect with `russh` on Tokio: password, key from the vault, SSH agent
- [ ] `known_hosts` in the vault: ask on first use with the SHA-256 fingerprint, refuse on change
- [ ] PTY shell channel, window-change on resize, keep-alive, clean disconnect and reconnect
- [ ] Bounded reads and no panics on anything the server sends

## M3: Terminal

- [ ] `cloudnode-term` over `alacritty_terminal`: grid, scrollback, selection, 256 colours and true colour
- [ ] GUI renderer: glyph atlas into a pixel buffer, redrawing only changed rows; cursor and selection in the theme
- [ ] Keyboard and mouse input, copy and paste, bracketed paste
- [ ] Performance budget: input to screen under one frame at 120×40

## M4: Desktop shell

- [ ] Title bar with the native macOS window buttons and session tabs; Windows and Linux equivalents
- [ ] Sidebar: search over hosts and keys, Favorites, Connected, groups, host editor
- [ ] Key Management: generate Ed25519 and RSA, import, export the public key, copy fingerprint
- [ ] Bundle Inter and JetBrains Mono (SIL OFL 1.1) with their `ATTRIBUTION.md` rows
- [ ] About window with Slint's "About Slint" attribution (required by Slint's license)
- [ ] Log file with rotation in the data folder; single running instance
- [ ] Interface translations (`@tr`), Russian first

## M5: Console app

- [ ] The vault, host lists and Key Management in `cloudnode-tui`
- [ ] Sessions in the TUI through the same `cloudnode-term` grid
- [ ] Log to a file, never to the console the TUI owns

## M6: Brand

- [ ] TradeCloud orange: replace the placeholder `#FF7A1A` with the brand's exact value
- [x] App icon: the running cheetah, with `.icns`, `.ico`, hicolor and 1024 px renders generated by `packaging/icons.py`; window icon in the Slint app
- [ ] Icon embedded in `cloudnode.exe` (Windows resource) and installed by the Linux packages

## M7: Releases

- [x] Every push to `main` builds a draft GitHub Release for macOS (universal DMG), Windows (portable zip) and Linux (tarball) with `SHA256SUMS.txt`; `develop` has no automatic builds
- [ ] Signing and notarization: Developer ID + notarized DMG, Authenticode for Windows
- [ ] Installers: Windows MSI, Linux AppImage, `.deb` and `.rpm`; ARM builds for Windows and Linux
- [ ] Slint attribution on the download page as well as in the About window
